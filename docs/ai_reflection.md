# AI Reflection

Throughout the project, AI assistance was most effective when it was provided with a specific and traceable problem rather than a vague request for improvement. In entry #5, for example, I asked the AI to trace what would happen if `HouseholdRepository.load()` encountered a missing or malformed JSON file, rather than simply asking it to "fix errors." This led to two useful improvements. First, `readFile` was modified so that a missing file is treated as a valid empty result rather than causing the application to fail. Second, the review revealed that the `loadAll` methods in both repositories were almost identical. This resulted in the introduction of the generic `loadAllFrom[T]` helper, which removed the duplication at its source rather than applying separate fixes in two locations.

One of the clearest examples of AI providing misleading information (hallucination) occurred during the `sbt` tooling issues described in entry #13. While assisting with the build failure, the AI incorrectly stated that the `sbt` 2.x line only extended to 2.0.2 as of mid-2026, even though higher 2.0.x releases existed. It also assumed that IntelliJ's project wizard had selected a bleeding-edge `sbt` version instead of identifying the actual issue, which was that two version numbers had been placed in the wrong configuration files. Neither mistake prevented the final solution, since the underlying fix of using `sbt` 1.10.5 and `sbt-assembly` 2.2.0 was still correct. However, this experience demonstrated that specific claims about current software versions should be independently verified rather than accepted solely because they are presented confidently.

AI assistance also had a clear practical limitation in entry #14. A request to implement a complete `ChecklistScreen` together with an export helper exceeded the generation length, leaving an incomplete `ChecklistExporter.scala` that required a second pass to finish. This was not necessarily an incorrect solution, but it was an incomplete one. It reinforced the importance of reviewing AI-generated code for completeness as well as correctness, particularly when working on larger tasks involving multiple files and components.

Overall, AI was most valuable in this project as a rapid first-pass generator and as a second pair of eyes for identifying potential improvements, particularly duplicated logic and implementation issues that could otherwise have been overlooked during development. At the same time, the project demonstrated that AI should not be treated as an authoritative source for unverified information about external tools and should not be relied upon to complete large, multi-file tasks without supervision. Human review and independent verification remained necessary throughout the development process.
